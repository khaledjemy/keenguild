# KeenGuild Laravel development build

This is a new Laravel 12 application under `site/`. Its `/` route serves the current homepage from `../dist/index.html`, injecting catalog links into the response without rewriting that file during requests. Its `/assets/*` route streams the original `../dist/assets` files, including video, without duplicating the 90+ MB asset directory. The Cloudflare agent remains a separate API service and the original bridge script is served at `/agent-api-bridge.js`.
For a different deployment, set both `KEENGUILD_AGENT_API_URL` (HTTPS) and `KEENGUILD_AGENT_SITE_KEY` in that deployment's `.env`. Laravel replaces only the homepage's agent connection metadata; the assistant code and data stay in Cloudflare. If neither is set, the existing design-file values remain for the local preview. If one value is supplied without the other, or a configured value fails validation, the browser bridge sees an incomplete connection instead of silently using a mismatched site identity. The site key is a public browser identifier, not a server-side secret; restrict allowed origins and manage private credentials in the standalone agent service.
The homepage's four service titles link to the corresponding Laravel detail pages only while those services are published. The language toggle is visible at mobile widths and updates those links between Arabic and English.
`/admin/homepage-heroes` lets the owner write a short bilingual kicker, two-line headline and description for the existing hero without changing its layout. The single entry starts as a private draft; only after it is reviewed and marked published does the Laravel homepage replace the static copy. If no approved entry exists, the original design and words remain intact. The public HTML escapes editor text and the language toggle switches the approved copy and description metadata.
The homepage Explore menu includes direct bilingual links to the Laravel services, pricing, work/demos and articles pages, so these pages remain reachable on mobile without scrolling to the footer.
The original showreel is roughly 61 MB. Its source is now assigned only as the visitor nears the video section; it autoplays muted when that section enters view and pauses when it leaves. This preserves the visual treatment while avoiding an eager video transfer on the initial homepage load.
The homepage journal keeps its clearly labeled design previews until an article is published with a publication time in the past. It then shows up to three latest published articles from the admin, using their approved title, summary, optional cover, and real detail-page link in both languages. Draft and scheduled articles never appear there. The journal's “Explore articles” link opens the Laravel article index even before any article is published.
The homepage selected-work section likewise keeps its fictional design studies until a public project is available. It then shows up to two featured/ordered published projects, with the project type clearly labeled. Client projects require explicit display permission; an external demo button appears only for a ready HTTPS demo. The full Work page still keeps the fictional concept demos separate from client projects.

## Local setup on this Windows machine

PHP 8.2, Composer and SQLite are available. XAMPP has `php_intl.dll`, but it is disabled in the global `php.ini`; this project includes `php-conf.d/intl.ini` for project-scoped CLI use.

In PowerShell from this directory:

```powershell
$env:PHP_INI_SCAN_DIR='D:\projects\private\keenguild\site\php-conf.d'
php artisan migrate
php artisan db:seed --class=CatalogDraftSeeder
php artisan db:seed --class=ApprovedWebPackagesSeeder
php artisan db:seed --class=AdditionalServicesSeeder
php artisan keenguild:create-admin
php artisan storage:link
php artisan serve --host=127.0.0.1 --port=8002
```

Before any public launch, run `php artisan keenguild:launch-check`. This read-only check requires a site administrator, at least one valid published official contact channel, complete bilingual published privacy and terms pages, the three approved public web packages, and the original homepage/agent bridge assets. If quote intake is enabled, it also verifies that both language versions can display a working privacy link and official contact path. A failed check changes no data. A passing check is **not** production approval: separately verify the actual company/legal text, HTTPS, backups, server hardening, responsive design and live integrations. The local development database may correctly fail until the owner supplies and approves those details.

Choose your own admin email and password at the hidden prompt. Do not put either in source control or chat. Open `/admin` to manage content, `/` for the existing homepage, `/ar/about` for the company introduction, `/ar/services` for services, `/ar/pricing` for the Arabic pricing page, `/ar/work` for projects, `/ar/articles` for the journal, and `/ar/faq` for FAQs. The corresponding `/en/` catalog pages are also available. The About page lists only published services and does not claim unverified team size or completed work. Articles and FAQs are bilingual, admin-editable, and unpublished by default; do not add invented claims as public content. Articles need both a publication flag and a publication time that has arrived. Article bodies are plain text, escaped on output, not rich HTML.

`/ar/contact` and `/en/contact` list only official contact channels approved in `/admin/contact-channels`. Add the real KeenGuild account URL for each platform and explicitly publish it. HTTPS links must be on the matching platform and point to an account path, not the platform homepage; Email accepts a validated address. The legacy homepage keeps its social icons, but Laravel renders their `href` values as the approved account URLs (or `#` for an unapproved placeholder) before JavaScript runs, so a crawler or visitor without JavaScript never receives an unrelated platform-homepage or assumed email link. No official channels are preloaded.

`/admin/legal-pages` lets the owner draft bilingual privacy and terms pages. Only a reviewed page marked published appears at `/ar/legal/privacy`, `/en/legal/privacy`, `/ar/legal/terms`, or `/en/legal/terms` and in the catalog footer. No legal wording is prefilled: the owner must supply and approve the real text. The body is escaped plain text, not executable HTML. Publishing a privacy page does not by itself enable quote collection; the inquiry flag and a valid published official contact channel are also required. Project/article image uploads accept only JPEG, PNG, WebP or AVIF (not SVG); covers are capped at 8 MB for projects and 4 MB for articles, with up to ten 8 MB gallery images per project.

The initial catalog seed creates seven service drafts, four package drafts, and seventeen option drafts. The owner has approved three starting prices and their basic scopes; `ApprovedWebPackagesSeeder` publishes landing (12,000 EGP, one page), company (27,000 EGP, up to five pages), and store (50,000 EGP, catalog/cart/basic orders). Payment and shipping integrations are separate. `AdditionalServicesSeeder` publishes the remaining five service descriptions and a custom-quote web-app package without a fixed price. This reflects the wider programming-service catalog while keeping websites the primary focus. Both approval seeds affect the local database only unless explicitly run on a server. All priced options and future projects remain unpublished. New projects default to `concept`. A client project requires both `published = true` and `display_permission_confirmed = true` before it appears publicly; the admin should retain proof of approval outside the site. Its demo link appears only when the URL is HTTPS and its demo status is `ready`.

Each approval seed records a one-time database marker. Re-running either never overwrites later admin edits or re-publishes an item hidden by an admin. On a fresh database they refuse to run until the draft catalog exists. Plain `php artisan db:seed` intentionally creates no fake user or catalog data.

## Price model

The calculator uses package base price plus selected additions, multiplied by editable complexity and urgency factors, rounded to 500 EGP. Fixed additions are charged once, per-unit additions multiply by quantity, and percentage additions are calculated against the package base (not against other additions). The page displays each line item, factors, rounded total, and a ±10% indicative range. This is not a binding quotation. The three web package base prices and basic scopes are owner-approved; additions and their prices are drafts, and the complexity/urgency factors are editable assumptions. Sources and scope are in `../PROJECT_PLAN.md`.
The five factor rows in `/admin/pricing-settings` have readable Arabic labels and can be edited within the 1–2 range. A sixth row controls the indicative range margin, initially ±10%, editable from 0–30%. Neither the factors nor the range margin change a package's published starting price. These rows cannot be deleted from that screen, because a deleted setting would otherwise silently revert to its default. Changing a setting updates estimates immediately.

Admins can open the private draft preview from the Packages screen or `/admin/preview/pricing/ar` (`/en` also works). It shows unpublished services, packages and options and has a separate admin-only estimate endpoint. Project rows also provide a private preview for unpublished case studies and demos. The public `/ar/pricing` and `/ar/work` never show these drafts. Preview pages are marked `noindex` and must not be shared as customer quotations or public portfolio links.

The Work page has a separate, clearly labeled concept-demo area for the three interface studies already present in the original homepage: Flowboard, Storefront, and Pulse. They now have standalone `/ar/demos/{slug}` and `/en/demos/{slug}` pages with local-only interactions. These are not stored as client projects, do not submit data or orders, and must never be represented as completed customer work. Real project entries remain admin-managed with optional independent HTTPS demo URLs.
Project details now have a separate bilingual scope-of-work field in addition to the narrative, cover, gallery and technology tags. The admin form rejects a ready demo URL that embeds credentials or points to a local hostname or IP address. Public demo buttons use the same check, so an older unsafe database value stays hidden until corrected. A demo is still optional; publication and client-display permission remain separate gates.

`/sitemap.xml` lists the public homepage, catalog routes, published services/projects/articles/legal pages, and the three labeled concepts in both languages. It excludes drafts, future articles, unapproved client work, quote forms and admin previews. Set the production `APP_URL` to the real HTTPS domain before launch so generated sitemap URLs are correct. `public/robots.txt` excludes the admin area from crawling; access control does not rely on robots rules.

## Quote requests

`/ar/request-quote` and `/en/request-quote` are ready, but the form is disabled by default. The POST endpoint refuses submissions until `KEENGUILD_INQUIRIES_ENABLED=true`, at least one valid official contact channel is published, and a real privacy policy is available. The policy may be the reviewed bilingual page published in `/admin/legal-pages` or an external `KEENGUILD_PRIVACY_URL` with HTTPS. After changing `.env`, run `php artisan config:clear` (or rebuild the config cache). The owner should first verify the policy, company contact details, retention process and access controls. Requests are stored locally in `quote_requests`, visible only to admins at `/admin/quote-requests`; no email is sent automatically. The form checks consent, a honeypot, field lengths, published package availability, and rate limits requests to five per minute. Never paste customer data into a public issue or chat.

## Before any public launch

- Confirm actual company contact details, legally appropriate privacy terms, and an intake process before accepting lead data.
- Review and approve each service, package, option and price before publishing.
- Add only real or clearly marked concept projects, with permission to display assets and valid demo URLs.
- The homepage is currently served from the existing static build, not yet converted to an editable Laravel template. Deploy `dist/index.html`, `dist/assets`, and `dist/agent-api-bridge.js` alongside `site/` until that conversion is complete; keep the asset route restricted to the existing asset directory.
- Configure MySQL and PHP `intl` on the production Linux host; never deploy a local `.env` or SQLite database.
- Verify responsive layout, RTL/LTR, links, accessibility, SEO, security and backups.
