# KeenGuild — Laravel site

This directory is the Laravel application for the KeenGuild website. The existing
homepage design lives in `../dist/` and is served by Laravel at `/`; the Arabic
and English catalog pages, pricing estimator, demo concepts, and admin panel live
here. Keep `site/` and `dist/` together when testing or packaging the site.
The public frontend uses Laravel views and the existing homepage markup; it has
no React, Inertia, or separate SSR service.

The Cloudflare customer assistant is a separate service. This repository contains
only the site's browser bridge (`../dist/agent-api-bridge.js`) and its public
connection settings. It does not contain or deploy the assistant backend.

## Local setup

Requirements: PHP 8.2+ with the extensions required by `composer.json`, Composer,
Node.js/npm, and a writable database. From this directory:

```sh
composer install
cp .env.example .env
php artisan key:generate
php artisan migrate
php artisan storage:link
npm install
npm run build
php artisan serve
```

The build also compiles the homepage Tailwind classes into
`../dist/assets/legacy.css`. Keep that generated file with `dist/`; the
homepage no longer loads Tailwind from a browser CDN.

The example environment uses SQLite. Create an empty `database/database.sqlite`
file if your PHP/Laravel setup does not create it automatically. On Windows,
copy `.env.example` to `.env` with your shell's equivalent of `cp`.
The local `php-conf.d/` directory is a Windows PHP workaround and is ignored by
Git; enable PHP's `intl` extension through the Linux server configuration instead.

`/admin` is the protected content panel. The first administrator must be created
explicitly with `php artisan keenguild:create-admin`; the normal database seeder
does not create a default login. Never commit `.env`, the local SQLite database,
or an administrator password.

## Content and pricing

`php artisan db:seed --class=CatalogDraftSeeder` adds editable catalog drafts;
review them in the admin panel before publishing. The three owner-approved
starting packages can be added/updated with
`php artisan db:seed --class=ApprovedWebPackagesSeeder`. Read `../PROJECT_PLAN.md`
for their approved starting prices, included scope, and the distinction between
those prices and unapproved add-on prices. Other services are quote-only until
their scope and price are approved.

The admin panel manages services, packages, price options, pricing factors,
projects and demo URLs, article categories and articles, FAQs, homepage copy and video, legal pages,
contact channels, and quote requests. The homepage journal shows only published,
scheduled articles; when none exist, it shows an empty state instead of the
static design previews. `/admin/homepage-videos` accepts an MP4 upload or a
direct HTTPS MP4 URL. A draft leaves the existing video untouched; publishing
the setting switches the video, and unpublishing restores the original.
Uploads are also subject to the PHP server's `upload_max_filesize` and
`post_max_size`. The ignored local `php-conf.d/uploads.ini` raises them for
the Windows development server; configure equivalent limits in PHP-FPM on
Linux. Use a direct HTTPS MP4 URL if the file exceeds the server limit.
A project needs permission and publish-ready
bilingual content before it can appear publicly. Add official contact links via
`/admin/contact-channels` when available; unpublished links stay hidden.

The homepage has no pricing section; its pricing links open the dedicated
`/ar/pricing` or `/en/pricing` page. Published package prices remain managed
from `/admin/packages`. The admin dashboard has an "إدارة الصفحة الرئيسية"
shortcut group. An older `featured_on_home` database flag is retained for
existing records but no longer controls the homepage.
The service editor has an "عرض بطاقة في الرئيسية" switch. The first four
published, selected services by sort order appear on the homepage. Existing
website, store, web-app and integration services were selected by migration;
unpublished or unselected services do not appear there. Each card links to
the real service detail page.
Use `/admin/homepage-contents` for bilingual section copy (proof cards, service
intro, demo cards, work/journal headings, showreel, contact and
footer). Empty pairs keep the original design copy. The hero and MP4 remain
under their existing dedicated editors; service card text, package prices,
featured projects, latest articles and social links are managed through their
respective catalog resources. Article categories are managed at `/admin/article-categories` and
appear on `/ar/articles/category/{slug}` and `/en/articles/category/{slug}` only
after they contain a published article. Main navigation and footer use real
HTML links to the catalog; `/sitemap.xml` and `/robots.txt` are generated by
Laravel. Set the production `APP_URL` to the final HTTPS domain so canonical,
alternate-language and sitemap URLs are correct.
The homepage has two server-rendered URLs: `/` for Arabic and `/en` for
English. The language button navigates between them, and both are listed in
the sitemap with canonical and alternate-language links. Review translated
homepage copy after major content edits before public deployment.

The homepage-content editor also accepts a site logo and favicon. Uploaded
assets replace the default mark on the homepage and catalog; the footer tagline
is shared between them. Public social links without an approved destination
are omitted from the footer.
The same editor accepts separate images for the floating orbit logo and the
contact-section background. Leave either field blank to retain the original
design asset. Uploaded images are served from public storage; run
`php artisan storage:link` on each installation.

Use `/admin/navigation-items` to edit, reorder, hide or add the primary menu,
expanded menu and footer links. Targets are restricted to known internal pages
and homepage sections. `/admin/seo-settings` controls the homepage title,
default description, sharing image and whether public pages request indexing.
It does not submit the sitemap to a search engine or guarantee indexing.
When indexing is disabled, the public sitemap becomes an empty XML urlset in
addition to the noindex tags and robots.txt crawl restriction. Re-enabling
indexing repopulates it from currently public content.
The admin dashboard explains the estimator formula and links to packages,
price options and factors. Projects have private Arabic/English page previews
from `/admin/projects`; a clickable interactive demo requires a separately
published public HTTPS URL marked ready. A screenshot gallery is not itself a
live demo.
Services and articles now also have Arabic and English preview actions in
their admin lists. They can show drafts before publication, require admin
access, send no-store headers, and request noindex. Public routes and the
sitemap still exclude unpublished services and articles.
If a project has uploaded cover/gallery images, its public detail page also
offers a clearly labelled, noindex design walkthrough at
`/{locale}/work/{slug}/tour`. Admins can inspect the same image tour for drafts
from the projects table; drafts remain 404 on the public route. The tour is
not presented as a working product, and it never exposes raw HTML uploads.
The project editor also has an "عرض في قسم جرّب بنفسك بالرئيسية" switch.
Only published projects with complete bilingual copy, display permission when
needed, and a ready public HTTPS demo are eligible. Up to three appear in the
homepage demos section by sort order, linking to their project page and the
independent live demo. Until one qualifies, the clearly labelled fictional
concept examples remain on the homepage. Those fictional concept pages remain
accessible to visitors but request noindex and are excluded from the sitemap;
published project detail pages stay eligible for indexing.
Use `/admin/page-contents` to edit the hero heading, intro and search-result
description of the about, services, pricing, work, articles, FAQ and contact
pages. Empty fields preserve the current design copy; article category titles
and descriptions remain tied to their individual category records.
The same editor covers the three "about" process cards and three pricing-method
cards. Its preview action opens the current public page. Homepage copy also
covers the expanded-menu cards, their safe on-page targets, short section
labels, reel button and header status; the homepage-content and hero lists have
a direct homepage preview button.

Quote intake is disabled by default. Do not enable
`KEENGUILD_INQUIRIES_ENABLED` until a reviewed bilingual privacy page (or a
valid HTTPS privacy URL) is available and the administrator is ready to handle
requests in `/admin/quote-requests`. Social/contact links are optional for
quote intake and may be added later. The price estimator is indicative, not a
binding quote.

The owner can also create the singleton record at `/admin/inquiry-settings`
and switch quote intake on or off there. Once that record exists, its toggle
overrides `KEENGUILD_INQUIRIES_ENABLED`; no record means the environment value
remains the fallback. Neither switch bypasses the privacy-policy requirement.
Run `php artisan migrate --force` on the target server before using this panel.

To configure the independent Cloudflare assistant, set
`KEENGUILD_AGENT_API_URL` and `KEENGUILD_AGENT_SITE_KEY` in `.env`. Do not set
these to a local Ollama/WSL endpoint for the public site. The site key is a
browser-side site identifier, not an admin password or private API secret.
The preserved `../dist/index.html` also has the existing public Cloudflare
connection for its standalone static preview. When both Laravel settings are
empty, that preview connection remains in use; when either setting is supplied,
Laravel validates and overrides both meta tags. Set both values for a different
site-specific assistant workspace. The backend, its owner credentials, and its
private data remain outside this repository.

## Verification and launch gate

```sh
php artisan test
php artisan keenguild:launch-check
```

The approved local privacy and terms copy can be installed with
`php artisan db:seed --class=ApprovedLegalPagesSeeder --force`. This seeder
preserves previously edited legal pages. It also publishes the owner-provided
contact address and enables quote intake only when both bilingual pages are
complete. Review the actual production hosting location and legal text before
deployment.

To move the current edited SQLite content to a fresh MySQL installation,
use `keenguild:content-transfer export PRIVATE_PATH` locally, upload its JSON
outside the public web root, run `migrate --force` on the server, then use
`keenguild:content-transfer import PRIVATE_PATH --replace-migration-defaults`
before creating an administrator. The importer refuses populated content tables
and excludes users, inquiries, sessions and cache. Do not run starter seeders
after importing the edited content. See `HOSTINGER_DEPLOY.md`.

Project inquiries are retained for 12 months. Configure the hosting scheduler
to run `php artisan schedule:run` every minute; the scheduled
`keenguild:prune-quote-requests` command deletes expired inquiries daily.
Without this server cron job, automatic deletion will not occur.

`launch-check` is read-only. A failure means required content or intake gates
are still incomplete; do not bypass it by inventing legal text, company contact
details, or portfolio projects. A public contact method is required by this
launch check: either the enabled quote form with its privacy gate or a verified
published contact channel. Before any public deployment, separately verify
the rendered desktop/mobile pages, HTTPS, backups, the production `.env`, and
that the web server serves only `site/public/` while `dist/` remains available
to the application outside the document root. This README does not perform a
deployment or configure hosting.
